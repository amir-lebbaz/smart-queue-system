## 💡 فلسفة المشروع والرؤية الهندسية

الأنظمة التقليدية لإدارة الطوابير تعاني من معضلتين رئيسيتين:
1. **التكلفة العالية والتعقيد الميداني:** تتطلب شراء كواشك استدعاء وطابعات تذاكر حرارية باهظة (أكثر من 120,000 دج) مع فواتير شهرية لا تنتهي لبكرات الورق وصيانة الأحبار.
2. **الاكتظاظ وتوتر قاعات الانتظار:** يُجبر المريض أو الزبون على الجلوس داخل القاعة في بيئة مغلقة ممتلئة بالضجيج والعدوى دون معرفة دقيقة لساعة دخوله.

**الحل الذي ابتكرته في هذا النظام:**  
إلغاء الحاجة التامة لأي أجهزة أو طابعات ورقية، وتحويل **هاتف المراجع نفسه إلى تذكرة رقمية حية** عبر مسح كود QR بكاميرا الهاتف (بدون تطبيق). يحسب النظام لحظياً ساعة دخوله بالدقيقة وعدد الأشخاص قبله، وينبّهه صوتياً عند اقتراب دوره ليحضر للصالة مرتاحاً، بينما يتحكم الطبيب أو المسير بكل شيء من هاتفه أو كمبيوتره عبر ريموت ذكي فائق الخفة.

## 🛠️ البنية التحتية والتقنيات المستخدمة (Tech Stack)

تم اختيار تقنيات المشروع بعناية لضمان أعلى معايير الأداء والسرعة وقابلية التوسع (High Concurrency):

- **الواجهة الأمامية والمسارات (Framework):** Next.js 15 (App Router) المبني على React 19.
- **لغة البرمجة الأساسية (Language):** TypeScript (مع كتابة Types و Interfaces صارمة لكافة الكائنات والاستجابات).
- **التصميم وتنسيق الواجهات (Styling):** Tailwind CSS مع لوحة ألوان داكنة وعصرية (Slate-Navy Palette) مريحة للعين ومتوافقة مع المعايير الطبية.
- **قاعدة البيانات السحابية (Cloud Database):** PostgreSQL 17 مستضافة على Supabase عبر واجهة REST API المباشرة ومعالجة تجمّع الاتصالات (Connection Pooling).
- **شبكة التوزيع وكاش الحافة (CDN & Edge Caching):** Vercel Edge Network مع ترويسات `s-maxage` و `stale-while-revalidate`.
- **محركات الصوت والنداء (Audio APIs):**
  - توليد نغمات التنبيه خوارزمياً عبر `Web Audio API` (Synthesizer Oscillators).
  - النداء الصوتي باللغة العربية الفصحى عبر `Web Speech API`.
- **إدارة طاقة الشاشة (Device APIs):** `Screen Wake Lock API` لإبقاء شاشات التلفاز والهواتف متيقظة دون انطفاء أثناء الانتظار.
- **توليد الأكواد (QR Engine):** مكتبة `qrcode` لتوليد رموز فيكتورية رقمية دون استدعاء أي سيرفرات خارجية.

## 🏛️ البنية المعمارية وقابلية التوسع (System Architecture)

```
                       ┌───────────────────────────────┐
                       │     المراجعون والزوار         │
                       │   (هواتف ذكية iPhone/Android) │
                       └───────────────┬───────────────┘
                                       │ HTTP / QR Scan
                                       ▼
                       ┌───────────────────────────────┐
                       │   Vercel Global Edge Network  │
                       │  (Edge Cache: s-maxage=2s)    │
                       └───────────────┬───────────────┘
                                       │ Misses only (~2%)
                                       ▼
                       ┌───────────────────────────────┐
                       │   Next.js 15 Serverless Core  │
                       │   (/api/organizations/...)    │
                       └───────────────┬───────────────┘
                                       │ Secure HTTPS
                                       ▼
                       ┌───────────────────────────────┐
                       │   Supabase PostgreSQL 17      │
                       │  (queue_orgs & queue_tickets) │
                       └───────────────────────────────┘
```

### كيف يتعامل النظام مع مئات آلاف المستخدمين المتزامنين؟
1. **كاش الحافة الذكي (Edge Caching):**  
   تم ضبط مسارات الاستعلام عن حالة الطابور بترويسة:  
   `Cache-Control: public, s-maxage=2, stale-while-revalidate=4`  
   لو كان هناك 5,000 مراجع ينتظرون في نفس العيادة، يصل طلب **واحد فقط** كل ثانيتين إلى قاعدة البيانات، بينما يحصل الباقون على النتيجة في أقل من 15 ميلي ثانية من أقرب سيرفر CDN.
2. **التخزين السحابي الدائم (Persistent Cloud State):**  
   تم فصل حالة الطوابير والتذاكر تماماً عن بيئات الخوادم المؤقتة (Serverless Containers) وتخزينها في قاعدة بيانات سحابية مركزية متزامنة فورياً عبر كافة الأجهزة.

## 🚀 الميزات والحلول الهندسية الميدانية المبتكرة

### 1. دورة حياة الحضور ثلاثية المراحل (3-State Workflow)
بدل الأنظمة السطحية التي تكتفي بزر استدعاء وحيد، برمجت منطقاً ميدانياً يحاكي واقع العمل الحقيقي:
- **مرحلة الاستدعاء (`called`):** يُنادى على الرقم بصوت الجرس والنداء العربي.
- **مرحلة تأكيد الدخول (`serving`):** يؤكد الطبيب دخول المراجع للغرفة.
- **مرحلة الإنهاء والخروج التلقائي (`completed`):** عند ضغط المسير على إنهاء الخدمة، تخرج التذكرة من الطابور فورياً وتتحول شاشة هاتف المراجع تلقائياً إلى شاشة شكر وتقييم بلمسة واحدة (😄 ممتازة / 😐 عادية / 🙁 تحتاج تحسين).

### 2. نظام التأجيل الذكي (Smart Hold Algorithm)
إذا نودي على مراجع ولم يكن متواجداً في القاعة:
- ينقر الطبيب على **"تأجيل (Hold)"**.
- ينتقل المراجع إلى قائمة التذاكر المجمدة، ويُستدعى الرقم الذي يليه فوراً لعدم تعطيل العمل.
- عند عودة المراجع، يستدعيه الطبيب بنقرة واحدة **"حضر الآن"** فيدخل كأولوية قصوى.

### 3. دعم أصحاب الهواتف العادية وكبار السن (Walk-in Ticket System)
لمن لا يملك هاتفاً ذكياً:
- زر **"تذكرة حضورية"** في ريموت المسير يتيح تسجيل الزبون برقم هاتفه العادي.
- يحسب النظام تلقائياً وقت العودة التقريبي بالساعة والدقيقة (`HH:MM`) ليغادر القاعة ويعود في وقته.
- يوفر النظام زر اتصال فوري لإجراء رنة سريعة (`Bip`) للزبون وقت حضوره.

### 4. ملصق الطاولة والجدار A4 الفيكتوري (Printable Stand)
- صممت قالب طباعة متقدم عبر `@media print` داخل `globals.css`.
- يطبع الطبيب أو السكرتير بضغطة زر واحدة ملصق A4 ناصع البياض وعالي الدقة، يتضمن كود QR وشعار المؤسسة وثلاث خطوات إرشادية للمراجعين.

### 5. محرك التقارير وتصدير Excel (UTF-8 BOM CSV Export)
- نافذة تحليلات يومية دقيقة تعرض عدد التذاكر المكتملة، الملغاة، المؤجلة، ومتوسط وقت الخدمة.
- تصدير فوري لتقرير اليوم بصيغة CSV مع إضافة ترميز `\uFEFF` (Byte Order Mark) لضمان فتح الملف في Microsoft Excel باللغة العربية السليمة دون أي تشوه في الحروف.

## 💻 التشغيل والتطوير المحلي (Local Development)

```bash
# 1. استنساخ المستودع
git clone https://github.com/amir-lebbaz/smart-queue-system.git
cd smart-queue-system

# 2. تثبيت الحزم والمكتبات
npm install

# 3. إعداد متغيرات البيئة في ملف .env.local
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-service-role-or-anon-key

# 4. تشغيل خادم التطوير
npm run dev

# 5. البناء للإنتاج
npm run build
npm run start
```
